<section id='intro'>

`view` and `date` are controlled. The navigation actions never change the calendar: each computes the next view and
date and calls `onNavigate` with them, and the calendar moves when you pass them back in.

## Actions

| Action                     | Next view and date                                                                        |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| `next()`, `prev()`         | One period forward or back: the configured calendar period, `months`, `weeks`, or `days`. |
| `today()`                  | Today in `timeZone`, from the clock.                                                      |
| `goTo(date)`               | Same view, `date`.                                                                        |
| `setView(view, date?)`     | `view`, keeping the current date unless one is given.                                     |
| `navigate({ view, date })` | Either or both; omitted fields keep their current value.                                  |

`onNavigate` receives `{ view, date, range, period, inputRange }`. Because the next range arrives with the call, you can update the
URL or start fetching events for it before the calendar re-renders.

## Range and period

Every view and date resolve to three inclusive date ranges on `state.context`:

- **`period`** is the nominal span: a calendar period, `months` months, `weeks` whole weeks, or `days` days. Use it for titles.
- **`range`** is what is visible. Month-based day grids extend to whole weeks; other views use the period itself. Hidden dates remain inside this anchor envelope.

- **`inputRange`** covers the source dates needed by visible windows, including the following morning for overnight windows. Fetch events for it.

| View                           | Period                                      | Range                                                                 |
| ------------------------------ | ------------------------------------------- | --------------------------------------------------------------------- |
| Day grid, month-based duration | The calendar period or month count          | Padded to full weeks; six weeks per month with `fixedWeekCount: true` |
| Day grid, `weeks`              | `weeks` whole weeks from the week of `date` | Same as period                                                        |
| Time grid or list, `days: 7`   | The week containing `date`                  | Same as period                                                        |
| Time grid or list, other       | `days` days starting at `date`              | Same as period                                                        |

All four factories support `days`, `weeks`, `months`, and calendar `period` settings. Calendar quarters begin in January, April, July and October. A `months: 3` period starts with the anchor month instead.

<include lang='ts'>../../../examples/core/view-variants.ts#periods</include>

Weeks start on the `firstDayOfWeek` option, from `1` (Monday) to `7` (Sunday, the default). Input filtering uses `inputRange`; layout projection then clips to visible dates and hours.

To get the range for any view and date without a calendar, for example to fetch on the server, use
`getCalendarNavigation`:

```ts
import { getCalendarNavigation } from '@calendar-tsx/core';

const { range, period, inputRange } = getCalendarNavigation(
  views.views,
  'month',
  Temporal.PlainDate.from('2026-03-11'),
  {
    firstDayOfWeek: 1,
  },
);
```
