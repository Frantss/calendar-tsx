## Duration and navigation

Choose exactly one of `days`, `weeks`, `months`, or `period`. Counts must be positive integers.

| Setting  | Period                                                               | Navigation                                              |
| -------- | -------------------------------------------------------------------- | ------------------------------------------------------- |
| `days`   | Days starting on `date`; `7` retains week alignment.                 | Advances that many days.                                |
| `weeks`  | Whole weeks starting on `firstDayOfWeek`.                            | Advances that many weeks, preserving the weekday.       |
| `months` | Whole months starting with the month of `date`.                      | Advances that many months, landing on the first day.    |
| `period` | `'month'`, `'quarter'`, or `'year'`, aligned to the calendar period. | Advances one calendar period, landing on its first day. |

Day ranges use one row. Week ranges use one row per week. Month-based ranges are padded to full weeks; padding days have `isOutside: true`. A continuous year uses one section containing its weeks.

## Grouping

`groupBy` accepts `'month'`, `'resource'`, or an ordered tuple of those distinct keys. Month grouping requires a month-based duration.

| `groupBy`                      | Result                                                                        |
| ------------------------------ | ----------------------------------------------------------------------------- |
| omitted                        | One continuous grid.                                                          |
| `'month'` or `['month']`       | One section per month.                                                        |
| `'resource'` or `['resource']` | Resource columns within the grid.                                             |
| `['month', 'resource']`        | Month sections, each containing resource columns.                             |
| `['resource', 'month']`        | Each resource's month sections, in resource input order and then month order. |

`groupOrder: 'resource-first'` keeps each resource's dates together inside a row and lets bars span them. `'date-first'` groups columns by date and splits bars at resource boundaries. It does not change the outer section order chosen by `groupBy`.

An event appears in every resource it names. Unassigned events appear only in ungrouped grids. A background event without resource IDs shades all resources. A cell has `isUnavailable` when its resource has no availability overlapping that day.

## Visibility and overflow

| Setting                          | Description                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `hiddenDays`                     | ISO weekdays to omit, `1` for Monday through `7` for Sunday. At least one weekday must remain visible.  |
| `fixedWeekCount`                 | Show six rows per month. Allowed for `period: 'month'`, or when grouping by month. Defaults to `false`. |
| `maxEventsPerDay`                | Visible bar rows per grid row. Further rows are hidden and counted; `Infinity` removes the cap.         |
| `dayOverflow(date, resourceId?)` | Marks a date/resource cell as having more events, such as events not loaded yet.                        |

Hidden weekdays do not change `period`, its inclusive fetch `range`, or navigation steps. Bars project onto the remaining columns; events entirely on hidden dates disappear. A selected range with no visible dates has no rows. See [overflow](../features/overflow).

## Model

`layout` is `{ kind: 'dayGrid', sections }`. The view context also has `kind: 'dayGrid'`.

Each section has `key`, `period`, `range`, optional `month` and `resource`, header `columns`, `columnCount`, and `rows`. A section's month is its first date. Its `isOutside` flags are relative to that section's period, so a date may be an outside day in one month and an inside day in the next.

Each row has `key`, `days`, bar `segments`, `backgroundEvents`, `columnCount`, and `stackCount`, the number of visible bar rows. Columns contain `key`, `date`, and optional `resource`. Day cells add these fields:

| Day field       | Description                                                      |
| --------------- | ---------------------------------------------------------------- |
| `isOutside`     | The date pads the section and lies outside its period.           |
| `isToday`       | The date is today in `timeZone`.                                 |
| `isUnavailable` | The resource has no availability overlapping this date.          |
| `hiddenCount`   | Hidden bar segments crossing this cell.                          |
| `hasMore`       | `hiddenCount > 0`, or `dayOverflow` returned `true`.             |
| `events`        | Events on this date/resource, including hidden events, in order. |

| Bar segment field                   | Description                                                                  |
| ----------------------------------- | ---------------------------------------------------------------------------- |
| `event`                             | The event, in the calendar's time zone.                                      |
| `colStart`, `colSpan`               | First visible column, zero-based, and the number of visible columns covered. |
| `row`                               | Stack row, zero-based.                                                       |
| `continuesBefore`, `continuesAfter` | The event extends beyond the visible dates at that bar's edges.              |

Keys are stable within their parent. Render background events before bars. [Background layers](../features/background-layers) decorate each cell and respect its resource scope.

| Part                            | Model prop    | Element  | Notes                                                                                    |
| ------------------------------- | ------------- | -------- | ---------------------------------------------------------------------------------------- |
| `DayGridView`                   | `model`       | `div`    | Region labelled "Calendar". Contains sections.                                           |
| `DayGridViewSection`            | `section`     | `div`    | `role='grid'`; emits `--cal-columns`, `data-month`, and `data-resource-id`.              |
| `DayGridViewSectionHeader`      | none          | `div`    | Consumer-supplied month or resource label.                                               |
| `DayGridViewHeader`             | none          | `div`    | `role='row'`.                                                                            |
| `DayGridViewHeaderCell`         | `column`      | `div`    | `role='columnheader'`, `data-weekday`, `data-resource-id`.                               |
| `DayGridViewRow`                | `row`         | `div`    | `role='row'`; emits column and stack counts.                                             |
| `DayGridViewDay`                | `day`         | `div`    | `role='gridcell'`, `data-today`, `data-outside`, `data-unavailable`, `data-resource-id`. |
| `DayGridViewDayTrigger`         | `day`, `view` | `button` | Navigates to `view` on this date.                                                        |
| `DayGridViewRowEvent`           | `segment`     | `button` | A bar across the row's visible columns.                                                  |
| `DayGridViewRowBackgroundEvent` | `segment`     | `div`    | An all-day background span; `aria-hidden`.                                               |
| `DayGridViewDayBackground`      | `background`  | `div`    | A background layer's shading; `aria-hidden`.                                             |
| `DayGridViewOverflow`           | `day`         | `button` | Renders only when `day.hasMore`.                                                         |

Render each section's header and rows inside `DayGridViewSection`. Bars belong inside their row, alongside its day cells. The default theme arranges sections responsively; override `--calendar-section-min-width` or style the root's grid to choose another arrangement.
