`@calendar-tsx/themes` styles the parts of the React and Solid bindings. The stylesheets select parts by their
`data-scope`/`data-part` attributes and lay them out from the `--cal-*` geometry the parts emit, so they need no
JavaScript and no class names.

## Install

```npm
npm i @calendar-tsx/themes
```

Import one theme, and optionally a density after it:

```ts
import '@calendar-tsx/themes/default.css';
import '@calendar-tsx/themes/compact.css';
```

## Files

| File                | Contents                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| `base.css`          | Positioning only: month bars, time-grid columns and lanes, the now line. Every theme imports it. |
| `default.css`       | `base.css` plus the default look.                                                                |
| `high-contrast.css` | Black on white and white on black, with outlined events.                                         |
| `shadcn.css`        | The default look with its tokens read from shadcn/ui's variables.                                |
| `revenuecat.css`    | The default look in RevenueCat's brand colors.                                                   |
| `stripe.css`        | The default look in Stripe's colors.                                                             |
| `compact.css`       | Density only: smaller slots, bars and text. Import it after any theme.                           |

Import `base.css` alone to write
[your own look](custom-themes) on top of working layout.

## Layers

Every file declares the same cascade layers, in this order:

```css
@layer calendar.base, calendar.theme, calendar.density;
```

`base.css` fills `calendar.base`, themes fill `calendar.theme` and `compact.css` fills `calendar.density`, so a density
wins over any theme whatever the import order. All selectors are wrapped in `:where()`, with zero specificity.

As a result, your own unlayered CSS always wins over the themes without `!important`. CSS in your own layers wins only
when those layers come after the calendar's. See [overriding rules](customizing#overriding-rules).

## Expected composition

The layout assumes the parts are nested as the [view pages](../views/month-view) show them:

- `MonthViewWeek` holds its `MonthViewDay` cells and `MonthViewWeekEvent` bars.
- `TimeGridView` holds `TimeGridViewHeader`, an optional `TimeGridViewAllDay` and `TimeGridViewBody`.
- `TimeGridViewBody` holds an optional `TimeGridViewAxis` and the `TimeGridViewColumn`s.

## Built-in themes

Each theme imports `base.css` itself, so import exactly one of them.

### Default

```ts
import '@calendar-tsx/themes/default.css';
```

A neutral look with a rust accent. Colors follow the inherited `color-scheme` through `light-dark()`, and every
value is a [token](customizing#tokens) you can override. It sets no font family; the calendar inherits
the page's.

Events are tints of the accent, so changing `--calendar-accent` alone recolors the calendar. See
[accent](customizing#accent).

### High contrast

```ts
import '@calendar-tsx/themes/high-contrast.css';
```

`high-contrast.css` replaces `default.css` for people who choose more contrast: black on white in light mode, white on
black in dark mode.

- Every text pairing is 9:1 or more, above WCAG AAA's 7:1.
- Borders are 5.3:1 or more against the surface. Against muted surfaces, such as days outside the month, they are
  4.47:1 in light mode and 5.1:1 in dark mode.
- Events are outlined instead of tinted: the surface with a 2px border in the text color, and semibold text.
  `--calendar-event` and `--calendar-event-border` still override the outline.
- A bar that continues past a week edge, or a time-grid event that continues past midnight, gets a dashed edge, so
  continuation does not depend on a missing corner radius.
- Focus rings are 3px, and corners are tighter.
- The accent is deep blue (`#0035a8`) in light mode and yellow (`#ffd500`) in dark mode.

This theme is separate from Windows High Contrast. Under `forced-colors: active` the browser chooses the colors, and
every theme falls back to the default theme's [forced-colors rules](customizing#forced-colors).

### shadcn/ui

```css
@import 'tailwindcss';
@import '@calendar-tsx/themes/shadcn.css' layer(components);
```

`shadcn.css` replaces `default.css`. It maps the calendar tokens onto shadcn/ui's variables, so the calendar follows
the app's palette, radius and dark mode with no further setup:

| Calendar token                                    | shadcn/ui variable                   |
| ------------------------------------------------- | ------------------------------------ |
| `--calendar-surface`, `--calendar-surface-muted`  | `--background`, `--muted`            |
| `--calendar-text`, `--calendar-text-muted`        | `--foreground`, `--muted-foreground` |
| `--calendar-border`                               | `--border`                           |
| `--calendar-accent`, `--calendar-accent-contrast` | `--primary`, `--primary-foreground`  |
| `--calendar-focus-ring`                           | `--ring`                             |
| `--calendar-radius`, `--calendar-bar-radius`      | `--radius`, `--radius` × 0.6         |

- Events take the default theme's accent tint, so they are `--primary` mixed 16% (fill) and 24% (border) into
  `--background`. shadcn's `--secondary`, `--muted` and `--accent` sit almost on the background in light mode, so they
  would not separate events from the grid.
- It expects the Tailwind v4 variable naming: full `oklch()` colors, not the v3 HSL channels.
- Dark mode follows shadcn's `.dark` class, on `<html>` or on any element around the calendar. `color-scheme` is not
  needed.

### RevenueCat

```ts
import '@calendar-tsx/themes/revenuecat.css';
```

`revenuecat.css` replaces `default.css` with RevenueCat's press-kit colors: monochrome black purple (`#1f1f47`) with
the brand colors as accents.

- The brand red (`#f2545b`) marks today and the now line, with black purple numbers on it.
- Royal blue (`#576cdb`) tints events and draws the focus ring.
- Dark mode uses black purple as the surface.
- On white the brand red has a 3.39:1 contrast ratio, too low for small text, so the theme keeps it to fills and lines.
  In light mode today's time-grid header uses the text color instead.

### Stripe

```ts
import '@calendar-tsx/themes/stripe.css';
```

`stripe.css` replaces `default.css` with the colors from the public `--hds-color-*` tokens on stripe.com.

- Blurple `#533afd` marks today and the now line, and tints events. It is a step deeper than the logo's `#635bff`, and
  takes white numbers at 6.19:1.
- Slate neutrals: `#061b31` text on white in light mode, white on `#0d1738` in dark mode, where the accent is `#7389ff`.
- Borders are one step stronger than Stripe's quieter borders, which would lose the grid.

This theme is not affiliated with or endorsed by Stripe. Stripe's [Marks Usage Terms](https://stripe.com/marks/legal)
cover its names, design elements and trade dress.

### Compact density

```ts
import '@calendar-tsx/themes/default.css';
import '@calendar-tsx/themes/compact.css';
```

`compact.css` sets size tokens only, for dashboards, sidebars and wide resource grids. It works with any theme.

| Token                          | Default     | Compact     |
| ------------------------------ | ----------- | ----------- |
| `--calendar-font-size`         | `0.875rem`  | `0.75rem`   |
| `--calendar-font-size-sm`      | `0.75rem`   | `0.6875rem` |
| `--calendar-font-size-xs`      | `0.6875rem` | `0.625rem`  |
| `--calendar-day-header-height` | `2.25rem`   | `1.75rem`   |
| `--calendar-bar-height`        | `1.375rem`  | `1.125rem`  |
| `--calendar-bar-gap`           | `2px`       | `1px`       |
| `--calendar-overflow-height`   | `1.5rem`    | `1.125rem`  |
| `--calendar-week-min-height`   | `6rem`      | `4.5rem`    |
| `--calendar-slot-height`       | `3rem`      | `2rem`      |
| `--calendar-axis-width`        | `4rem`      | `3.25rem`   |

The density sets these tokens on `:root` in a later layer. A token you set on an element around the calendar still
wins, because the element is closer than `:root`.
