`@calendar-tsx/themes` styles the parts of the React and Solid bindings. The stylesheets select parts by their
`data-scope`/`data-part` attributes and lay them out from the `--cal-*` geometry the parts emit, so they need no
JavaScript and no class names.

## Install

```npm
npm i @calendar-tsx/themes
```

Import one theme, and optionally a density and the print layer after it:

```ts
import '@calendar-tsx/themes/default.css';
import '@calendar-tsx/themes/compact.css';
import '@calendar-tsx/themes/print.css';
```

## Files

| File                | Contents                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| `base.css`          | Positioning only: day-grid bars, time-grid columns and lanes, the now line. Every theme imports it. |
| `default.css`       | `base.css` plus the default look.                                                                   |
| `high-contrast.css` | Black on white and white on black, with outlined events.                                            |
| `shadcn.css`        | The default look with its tokens read from shadcn/ui's variables.                                   |
| `material-ui.css`   | The default look with its tokens read from Material UI's CSS theme variables.                       |
| `revenuecat.css`    | The default look in RevenueCat's brand colors.                                                      |
| `stripe.css`        | The default look in Stripe's colors.                                                                |
| `fullcalendar.css`  | FullCalendar's classic theme, for apps migrating from it.                                           |
| `compact.css`       | Density only: smaller slots, bars and text. Import it after any theme.                              |
| `print.css`         | Print only: paper colors, outlined events, no scrolling. Import it after any theme.                 |

Import `base.css` alone to write
[your own look](custom-themes) on top of working layout.

## Layers

Every file declares the same cascade layers, in this order:

```css
@layer calendar.base, calendar.theme, calendar.density, calendar.print;
```

`base.css` fills `calendar.base`, themes fill `calendar.theme`, `compact.css` fills `calendar.density` and `print.css`
fills `calendar.print`, so a density wins over any theme, and print over both, whatever the import order. All selectors are wrapped in `:where()`, with zero specificity.

As a result, your own unlayered CSS always wins over the themes without `!important`. CSS in your own layers wins only
when those layers come after the calendar's. See [overriding rules](customizing#overriding-rules).

## Expected composition

`base.css` expects the parts nested as the [view pages](../views/day-grid-view) show them:

- `DayGridView` holds sections; each `DayGridViewSection` holds its header and rows. `DayGridViewRow` holds its `DayGridViewDay` cells and `DayGridViewRowEvent` bars.
- `TimeGridView` holds `TimeGridViewHeader`, an optional `TimeGridViewAllDay` and `TimeGridViewBody`.
- `TimeGridViewBody` holds an optional `TimeGridViewAxis` and the `TimeGridViewColumn`s.

## Built-in themes

### Default

```ts
import '@calendar-tsx/themes/default.css';
```

A neutral gray look with an ink accent for today, blue events and a red now line. Colors follow the inherited
`color-scheme` through `light-dark()`, and every value is a [token](customizing#tokens) you can override. It sets no
font family; the calendar inherits the page's.

Each role has its own color, so events, today, now, background events, unavailable time and weekends read apart. See
[roles](customizing#roles).

### High contrast

```ts
import '@calendar-tsx/themes/high-contrast.css';
```

`high-contrast.css` replaces `default.css` for people who choose more contrast: black on white in light mode, white on
black in dark mode.

- Every text pairing is 9:1 or more, above WCAG AAA's 7:1.
- Borders are 5.3:1 or more against the surface. Against muted surfaces, such as header bands, they are
  4.47:1 in light mode and 5.1:1 in dark mode.
- Timed events are outlined instead of tinted: the surface with a 2px border and a 4px stripe in the text color, and
  semibold text. All-day and multi-day bars are solid in the text color. `--calendar-event` and
  `--calendar-event-border` still override them.
- A bar that continues past a week edge, or a time-grid event that continues past midnight, gets a dashed edge, so
  continuation does not depend on a missing corner radius.
- Focus rings are 3px, and corners are tighter.
- The accent is deep blue (`#0035a8`) in light mode and yellow (`#ffd500`) in dark mode. The now line is red
  (`#c00000`, 6.48:1; `#ff8080`, 8.65:1) and background events green (`#006b4f`, `#5fe0b5`).

This theme is separate from Windows High Contrast. Under `forced-colors: active` the browser chooses the colors, and
every theme falls back to the default theme's [forced-colors rules](customizing#forced-colors).

### shadcn/ui

```css
@import 'tailwindcss';
@import '@calendar-tsx/themes/shadcn.css' layer(components);
```

`shadcn.css` replaces `default.css`. It maps the calendar tokens onto shadcn/ui's variables, so the calendar follows
the app's palette, radius and dark mode with no further setup:

| Calendar token                                              | shadcn/ui variable                   |
| ----------------------------------------------------------- | ------------------------------------ |
| `--calendar-surface`, `--calendar-surface-muted`            | `--background`, `--muted`            |
| `--calendar-text`, `--calendar-text-muted`                  | `--foreground`, `--muted-foreground` |
| `--calendar-border`                                         | `--border`                           |
| `--calendar-accent`, `--calendar-accent-contrast`           | `--primary`, `--primary-foreground`  |
| `--calendar-event-color`, `--calendar-event-color-contrast` | `--chart-1`, `--foreground`          |
| `--calendar-now`                                            | `--destructive`                      |
| `--calendar-background-event-color`                         | `--chart-2`                          |
| `--calendar-focus-ring`                                     | `--ring`                             |
| `--calendar-radius`, `--calendar-bar-radius`                | `--radius`, `--radius` × 0.6         |

- Events take `--chart-1`, apart from today's `--primary`. shadcn's `--secondary`, `--muted` and `--accent` sit almost on
  the background in light mode, so they would not separate events from the grid.
- Solid all-day bars write `--foreground` on `--chart-1`. shadcn's default charts are mid-lightness in light mode and
  mid-darkness in dark mode, so it reads on both; with a custom chart palette, check that pairing or set
  `--calendar-event-color-contrast`.
- It expects the Tailwind v4 variable naming: full `oklch()` colors, not the v3 HSL channels.
- Dark mode follows shadcn's `.dark` class, on `<html>` or on any element around the calendar. `color-scheme` is not
  needed.

### Material UI

```ts
import '@calendar-tsx/themes/material-ui.css';
```

`material-ui.css` replaces `default.css`. It maps the calendar tokens onto the CSS theme variables Material UI emits
with `cssVariables` enabled, so the calendar follows the app's palette, shape and color scheme:

| Calendar token                                              | Material UI variable                                                   |
| ----------------------------------------------------------- | ---------------------------------------------------------------------- |
| `--calendar-surface`, `--calendar-surface-muted`            | `--mui-palette-background-paper`, `--mui-palette-action-hover`         |
| `--calendar-text`, `--calendar-text-muted`                  | `--mui-palette-text-primary`, `--mui-palette-text-secondary`           |
| `--calendar-border`                                         | `--mui-palette-divider`                                                |
| `--calendar-accent`, `--calendar-accent-contrast`           | `--mui-palette-primary-main`, `--mui-palette-primary-contrastText`     |
| `--calendar-event-color`, `--calendar-event-color-contrast` | `--mui-palette-secondary-main`, `--mui-palette-secondary-contrastText` |
| `--calendar-now`                                            | `--mui-palette-error-main`                                             |
| `--calendar-background-event-color`                         | `--mui-palette-success-main`                                           |
| `--calendar-radius`, `--calendar-bar-radius`                | `--mui-shape-borderRadius`                                             |

Enable the variables in the MUI theme:

```ts
const theme = createTheme({
  cssVariables: { colorSchemeSelector: 'class' },
  colorSchemes: { light: true, dark: true },
});
```

- Without `cssVariables`, Material UI emits no variables and the calendar loses its colors.
- It expects the default `mui` variable prefix and `:root` as the `rootSelector`.
- Events take the secondary color, apart from today's primary.
- The muted surface is MUI's translucent hover color, which always sits on the opaque paper.
- Dark mode follows MUI's built-in `colorSchemeSelector` values: `media`, or `class`, `data` and
  `data-mui-color-scheme` set on `<html>` or on any element around the calendar. `color-scheme` is not needed. A
  custom selector, such as `[data-theme="%s"]`, works only on `<html>`.

### RevenueCat

```ts
import '@calendar-tsx/themes/revenuecat.css';
```

`revenuecat.css` replaces `default.css` with RevenueCat's press-kit colors: monochrome black purple (`#1f1f47`) with
the brand colors as accents.

- The brand red (`#f2545b`) marks today and the now line, with black purple numbers on it.
- Royal blue (`#576cdb`, with white at 4.59:1) colors events and draws the focus ring. Dark mode uses a lighter blue
  (`#8b9bf0`) with black purple text.
- Dark mode uses black purple as the surface.
- On white the brand red has a 3.39:1 contrast ratio, too low for small text, so the theme keeps it to fills and lines.
  In light mode today's time-grid header uses the text color instead.

### Stripe

```ts
import '@calendar-tsx/themes/stripe.css';
```

`stripe.css` replaces `default.css` with the colors from the public `--hds-color-*` tokens on stripe.com.

- Blurple `#533afd` colors events and the focus ring. It is a step deeper than the logo's `#635bff`, and takes white
  text at 6.19:1; dark mode uses `#7389ff`.
- Today is marked in slate (`#061b31` in light mode, white in dark mode), so it reads apart from the events.
- The now line is ruby (`#e2225f`, `#ea2261` in dark mode), and background events are green (`#00b261`).
- Slate neutrals: `#061b31` text on white in light mode, white on `#0d1738` in dark mode.
- Borders are one step stronger than Stripe's quieter borders, which would lose the grid.

This theme is not affiliated with or endorsed by Stripe. Stripe's [Marks Usage Terms](https://stripe.com/marks/legal)
cover its names, design elements and trade dress.

### FullCalendar classic

```ts
import '@calendar-tsx/themes/fullcalendar.css';
```

`fullcalendar.css` reproduces FullCalendar's classic theme (v7.1.3) on the calendar's parts, so an app moving off
FullCalendar keeps its look while it migrates.

- Today washes its cell and time-grid column in yellow (`#facc1526`) instead of taking a marker, and day numbers sit at
  the top end of the cell, underlined on hover.
- Events are solid `#3788d8` with white 12px text and a 4px radius. A timed single-day event in a day grid is an 8px dot
  and a bold title, with no fill, and list rows lead with a 10px dot.
- Weekends are unshaded, outside-month dates are faint (`#9ca3af`), non-business time is a flat faint fill and
  background events are a 15% green wash with no edge.
- The time grid has 25px slots with dotted slot lines and solid hour lines, and a 1px red (`#ef4444`) now line with an
  arrow at its start. List days are a full-width bold header band above their events.
- Borders are `#ddd`, text `#030712`, corners square.

The tokens read FullCalendar's own `--fc-classic-*` variables first, with the classic palette as the fallback, so an
app that customized FullCalendar's palette keeps its colors. Set those variables on `:root` or on the element that
carries `data-color-scheme`, as FullCalendar does. `data-color-scheme="dark"` switches to the classic dark palette, as
it does in FullCalendar; `color-scheme: dark` works too.

| Token                                                       | FullCalendar variable                                                       |
| ----------------------------------------------------------- | --------------------------------------------------------------------------- |
| `--calendar-surface`, `--calendar-surface-muted`            | `--fc-classic-background`, `--fc-classic-muted`                             |
| `--calendar-text`, `--calendar-text-muted`                  | `--fc-classic-foreground`, `--fc-classic-muted-foreground`                  |
| `--calendar-border`, `--calendar-border-strong`             | `--fc-classic-border`, `--fc-classic-strong-border`                         |
| `--calendar-accent`, `--calendar-focus-ring`                | `--fc-classic-primary`                                                      |
| `--calendar-event-color`, `--calendar-event-color-contrast` | `--fc-classic-event`, `--fc-classic-event-contrast`                         |
| `--calendar-now`, `--calendar-background-event-color`       | `--fc-classic-now`, `--fc-classic-background-event`                         |
| today's wash, non-business fill, outside-month dates        | `--fc-classic-today`, `--fc-classic-faint`, `--fc-classic-faint-foreground` |

Where it differs from FullCalendar:

- Event content is yours: FullCalendar renders times such as "9a" and "+2 more", and the calendar renders what you put
  in each part.
- FullCalendar gives timed events a 15px minimum height (`eventMinHeight`); set `minEventMinutes: 18` on the view for
  the same height at 25px slots. At the default 15 minutes, short events drop their top and bottom borders so their
  11px line still fits.
- List rows keep a 44px minimum height for touch, where FullCalendar's are about 37px.
- Timeline slot lines are solid rather than dotted.
- Outside-month dates are 2.54:1 against white, below WCAG AA, as in FullCalendar. Set
  `--fc-classic-faint-foreground` to raise them.

This theme is not affiliated with or endorsed by FullCalendar.

### Compact density

```ts
import '@calendar-tsx/themes/default.css';
import '@calendar-tsx/themes/compact.css';
```

`compact.css` sets size tokens only, for dashboards, sidebars and wide resource grids. It works with any theme.

| Token                          | Default     | Compact     |
| ------------------------------ | ----------- | ----------- |
| `--calendar-font-size`         | `0.875rem`  | `0.75rem`   |
| `--calendar-font-size-sm`      | `0.75rem`   | `0.6875rem` |
| `--calendar-font-size-xs`      | `0.6875rem` | `0.625rem`  |
| `--calendar-day-header-height` | `2.25rem`   | `1.75rem`   |
| `--calendar-bar-height`        | `1.375rem`  | `1.125rem`  |
| `--calendar-bar-gap`           | `2px`       | `1px`       |
| `--calendar-overflow-height`   | `1.5rem`    | `1.125rem`  |
| `--calendar-row-min-height`    | `6rem`      | `4.5rem`    |
| `--calendar-slot-height`       | `3rem`      | `2rem`      |
| `--calendar-axis-width`        | `4rem`      | `3.25rem`   |

The density sets these tokens on `:root` in a later layer. A token you set on an element around the calendar still
wins, because the element is closer than `:root`.

### Print

```ts
import '@calendar-tsx/themes/default.css';
import '@calendar-tsx/themes/print.css';
```

`print.css` applies only when printing, on top of any theme and density, so the printed calendar needs no separate
view. It fills a fourth layer, `calendar.print`, and changes nothing on screen.

- Browsers leave backgrounds out of a print unless the reader opts in, so nothing relies on a fill. Events are outlined
  in their event color with the text in black, solid all-day bars included, and today's marker is a black outline.
- Neutrals are black on white with `color-scheme: light`, so an app in dark mode still prints on paper. Event, now and
  background-event colors stay the theme's. With shadcn/ui or Material UI the event colors follow the app's dark
  variables, because those themes switch on a class rather than `color-scheme`.
- Slot and hour lines, unavailable hatching, background layers and background events print as drawn
  (`print-color-adjust: exact`).
- The now line is hidden.
- The time grid, timeline and list stop scrolling, drop a height limit set in a layer, and their headers stop sticking,
  so every hour prints from the top. A height limit in your own unlayered CSS, on the calendar or its container, still
  cuts it; lift it in a `@media print` rule.
- Month weeks, months in a year view, list days, timeline rows and events avoid breaking across pages.
- A timeline prints at the width it lays out, so a long range is cut at the page edge. Use landscape, a shorter range or
  a smaller `minSlotWidth` on the view.
