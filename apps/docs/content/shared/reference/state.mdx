| Field     | Type                     | Description                                                                     |
| --------- | ------------------------ | ------------------------------------------------------------------------------- |
| `context` | `Calendar_ViewContext`   | `view`, `kind`, `date`, `range`, `period` and `inputRange` of the current view. |
| `layout`  | `Calendar_Layout`        | The render model for the active view; switch on `layout.kind`.                  |
| `now`     | `Temporal.ZonedDateTime` | The clock's current time in `timeZone`.                                         |

Registered [features](../extending/features#state) add their state slices next to these.

`dateSelectionFeature` adds `selectedRange: Calendar_Selection | null`. Control it with `state` and
`onSelectionChange`, or provide an external `atoms.selectedRange` store. Transient editing state is separate:
`calendar.api.interactions.store.state` contains the session, candidate, outcome and preview. Draft changes do not
rebuild the base layout. See [interaction ownership](../features/interactions#state-and-ownership).

`layout` is typed as the union of the layouts your views use, so only those cases need handling. Each layout's model is
documented with its view:

| `layout.kind` | Model                                                                                                |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| `'dayGrid'`   | [Day grid view](../views/day-grid-view#model)                                                        |
| `'timeGrid'`  | [Week and day view](../views/week-and-day-view#model), [resource view](../views/resource-view#model) |
| `'list'`      | [List view](../views/list-view#model)                                                                |
| `'timeline'`  | [Timeline view](../views/timeline-view#model)                                                        |

Every item in a model has a `key` that is stable across derivations within its parent, for use as a list key.

## Types

`Calendar_StateOf<typeof calendar>` is the state type of an instance. Where the instance is not in scope, build it from
your views: `Calendar_State<TData, TResourceData, typeof views>`.
