## `useCalendar`

```ts
const calendar = useCalendar(options);
```

Takes the [options](options) and returns the [instance](instance).

- The instance is created on the first render and kept for the component's lifetime.
- It mounts in a layout effect, which starts the clock, and unmounts with the component.
- Every render passes the current options through `~update`. The state re-derives only when a tracked option changed,
  so keep `views`, `features`, `events` and `resources` referentially stable between renders.

<Callout type='warn' title='Let the types infer'>
  Don't pass type arguments such as `useCalendar<Booking>(…)`: TypeScript then stops inferring the rest, and `view`
  and `onNavigate` widen to `string`. Type `events` instead, for example as `Calendar_EventInput<Booking>[]`.
</Callout>

## `CalendarProvider`

```tsx
<CalendarProvider value={calendar} locale='en-GB'>
  {children}
</CalendarProvider>
```

Puts an instance in context for the parts and `useCalendarSelector`. Every part must render inside a
`CalendarProvider` or `Calendar`, or it throws.

| Prop     | Type                  | Default   | Description                                      |
| -------- | --------------------- | --------- | ------------------------------------------------ |
| `value`  | The calendar instance | —         | Usually from `useCalendar`.                      |
| `locale` | `string`              | `'en-US'` | Locale for the parts' default accessible labels. |

## `Calendar`

`useCalendar` and `CalendarProvider` in one component: it takes the options, including `locale`, plus `children`. Use
it when nothing outside the tree needs the instance.

## `useCalendarSelector`

Selects from the calendar's [state](state) in context, and re-renders when the selected value changes by `===`.

The context cannot carry the instance's types, so the state defaults to the widest type: every layout kind, and events
with `data: unknown`. Annotate the selector's parameter with `Calendar_StateOf<typeof calendar>`, or build the type from
your views with `Calendar_State`.

## `useCalendarContext`

Returns `{ instance, locale }` from the nearest provider, with the instance's types erased. Parts use it; you rarely
need it.

## `useCalendarEventStore`

The [event store](/docs/react/features/events#event-store), created once per component. It returns `add`, `update`,
`remove` and `reset`, plus `events`, the current list, which re-renders the component when it changes.
