## `useCalendar`

```ts
const calendar = useCalendar(options);
```

Takes the same [options](/docs/core/options) as `createCalendar` and returns the [instance](/docs/core#the-instance).

<Callout type='warn' title='Let the types infer'>
  Don't pass type arguments such as `useCalendar<Booking>(…)`: TypeScript then stops inferring the rest, and `view`
  and `onNavigate` widen to `string`. Type `events` instead, for example as `Calendar_EventInput<Booking>[]`.
</Callout>

- The instance is created on the first render and kept for the component's lifetime.
- It mounts in a layout effect, which starts the clock, and unmounts with the component.
- Every render passes the current options through `~update`. The state re-derives only when a
  [tracked option](/docs/core/options) changed, so keep `views`, `features`, `events` and `resources` referentially
  stable between renders.

`calendar.api` holds the [navigation actions](/docs/core/views-and-navigation#actions) and any actions from features.
Call them from your own controls.

## `CalendarProvider`

```tsx
<CalendarProvider value={calendar} locale='en-GB'>
  {children}
</CalendarProvider>
```

Puts an instance in context for the parts and `useCalendarSelector`. Every part must render inside a
`CalendarProvider` or `Calendar`, or it throws.

| Prop     | Type                  | Default   | Description                                      |
| -------- | --------------------- | --------- | ------------------------------------------------ |
| `value`  | The calendar instance | —         | Usually from `useCalendar`.                      |
| `locale` | `string`              | `'en-US'` | Locale for the parts' default accessible labels. |

## `Calendar`

```tsx
<Calendar {...options}>{children}</Calendar>
```

`useCalendar` and `CalendarProvider` in one component: it takes the calendar options, including `locale`, plus
`children`. Use it when nothing outside the tree needs the instance; use `useCalendar` when your own controls call
`calendar.api`.

## `useCalendarSelector`

```ts
const layout = useCalendarSelector((state: State) => state.layout);
```

Selects from the calendar's [state](/docs/core/layouts) in context and re-renders when the selected value changes.

The context cannot carry the instance's types, so the state defaults to the widest type: every layout kind, and events
with `data: unknown`. Annotate the selector's parameter to narrow it:

```ts
import type { Calendar_StateOf } from '@calendar-tsx/core';

type State = Calendar_StateOf<typeof calendar>;
```

Where the instance is not in scope, build the type from your views instead:
`Calendar_State<TData, TResourceData, typeof views.views>`.

Select the smallest slice you need. Return stable values: a new object or array from the selector re-renders on every
state change.

## `useCalendarContext`

Returns `{ instance, locale }` from the nearest provider, with the instance's types erased. Parts use it; you rarely
need it.

## `useCalendarEventStore`

```ts
const eventStore = useCalendarEventStore<Booking>(initialEvents);

const calendar = useCalendar({ ...options, events: eventStore.events });

eventStore.add([booking]);
```

The [managed event store](/docs/core/events-and-resources#managed-event-store), created once per component. It returns
the store's `add`, `update`, `remove` and `reset`, plus `events`, the current list, which re-renders the component when
it changes.
