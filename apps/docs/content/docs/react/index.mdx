`@calendar-tsx/react` creates a calendar from React state and renders it with unstyled parts for day-grid, time-grid,
list and timeline views, with or without resources. The parts emit their layout as data attributes and CSS custom properties, so you style them
with a theme or your own CSS.

<Callout title='Experimental'>The API can change or be removed in any release, without notice.</Callout>

## Install

```npm
npm i @calendar-tsx/react @calendar-tsx/core temporal-polyfill
```

- React 18 or 19.
- `@calendar-tsx/core` holds the view factories (such as `dayGridView`) and the types; the React package builds on it.
- `temporal-polyfill` provides `Temporal`, which every date and time uses. Import `Temporal` from it until your
  runtimes ship it natively.

### Styles

The parts are unstyled. For a working look, add the themes package and import one theme:

```npm
npm i @calendar-tsx/themes
```

```ts
import '@calendar-tsx/themes/default.css';
```

See [themes](/docs/react/recipes/themes), or [Tailwind](/docs/react/recipes/tailwind) if your app uses it.

### What it does

1. `calendarFeatures` configures the features once, `calendarViews` binds the views to them, and `useCalendar`
   receives both.
2. `view` and `date` live in React state. The buttons call `calendar.api`, which reports the next view and date to
   `onNavigate`; setting them moves the calendar.
3. `CalendarProvider` makes the calendar available to the parts.
4. `Month` selects the layout, checks its kind and renders the day-grid parts. The selector's state type is annotated,
   because the context does not carry the calendar's types.

<Callout type='warn' title='Let the types infer'>
  Don't pass type arguments such as `useCalendar<Booking>(…)`: TypeScript then stops inferring the rest, and `view`
  and `onNavigate` widen to `string`. Type `events` instead, for example as `Calendar_EventInput<Booking>[]`.
</Callout>
