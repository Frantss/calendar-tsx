title: Core
description: The framework-agnostic calendar engine.
---

`@calendar-tsx/core` turns a view, a date and a list of events into a render-ready model: day grids with spanning
bars, time grids with overlap lanes and resource columns, lists and resource timelines. It owns no DOM and no styles.
Use it from plain TypeScript, from a framework without bindings, or to write bindings of your own. For React or
Solid, start with their bindings, which use this package for you.

<Callout title='Experimental'>The API can change or be removed in any release, without notice.</Callout>

## Install

```npm
npm i @calendar-tsx/core temporal-polyfill
```

Every date and time the core accepts or returns is a [Temporal](https://tc39.es/proposal-temporal/docs/) value. Import
`Temporal` from `temporal-polyfill` until your runtimes ship it natively.

The core keeps its state in [TanStack Store](https://tanstack.com/store), which installs with it.

For styles, the [themes](/docs/core/recipes/themes) work with any markup that renders the parts' attributes.

### What it does

1. `createCalendar` derives the state from the options. `view` and `date` are controlled, so `onNavigate` passes
   the next ones back in through `~update`.
2. `~mount` starts the clock; the returned function stops it.
3. `store.subscribe` re-renders when the state changes. `store.state.layout` is the model for the active view.
4. The renderer writes `data-scope`, `data-part`, state attributes and `--cal-*` custom properties, the contract the
   [themes](/docs/core/recipes/custom-themes) read, so the default theme lays it out.

<Callout type='warn' title='Let the types infer'>
  Don't pass type arguments such as `createCalendar<Booking>(…)`: TypeScript then stops inferring the rest, and view
  keys widen to `string`. Type `events` instead, for example as `Calendar_EventInput<Booking>[]`.
</Callout>
