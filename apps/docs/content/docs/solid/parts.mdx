The Solid parts have the same names, model props, elements, roles, data attributes and `--cal-*` variables as the
React parts. The [React parts reference](/docs/react/parts) applies to both, including which parts render conditionally
and how [triggers](/docs/react/parts#triggers) navigate. Compose them with `<For>` and `<Show>`:

```tsx
<TimeGridView model={grid()}>
  <TimeGridViewHeader>
    <For each={grid().columns}>
      {column => (
        <TimeGridViewColumnHeader column={column}>
          <TimeGridViewColumnTrigger column={column} view='day'>
            {column.date.toLocaleString('en-US', { weekday: 'short', day: 'numeric' })}
          </TimeGridViewColumnTrigger>
        </TimeGridViewColumnHeader>
      )}
    </For>
  </TimeGridViewHeader>
  <TimeGridViewBody model={grid()}>
    <For each={grid().columns}>
      {column => (
        <TimeGridViewColumn column={column}>
          <For each={column.segments}>
            {segment => <TimeGridViewEvent segment={segment}>{segment.event.data.title}</TimeGridViewEvent>}
          </For>
          <TimeGridViewNowIndicator column={column} />
        </TimeGridViewColumn>
      )}
    </For>
  </TimeGridViewBody>
</TimeGridView>
```

## Props

Parts accept the props of their element, merged with the part's own. Merged props stay reactive.

- Most props: yours win.
- `class`: joined. Parts take `class`, not `className`.
- `style`: shallow-merged, so the `--cal-*` geometry survives your styles.
- Event handlers and `ref`: both run, in order. On triggers your `onClick` runs before the navigation, so
  `preventDefault()` skips it.

A handler in Solid's bound form, `onClick={[handler, data]}`, replaces the part's handler instead of chaining with it.
Use a plain function on triggers.

## `render`

`render` takes a function only. Solid has no elements to clone, so React's `render={<El />}` form does not exist.

```tsx
<ListViewEvent event={event} render={(props, event) => <a {...props({ href: `/bookings/${event().id}` })} />}>
  {event.data.title}
</ListViewEvent>
```

- `props(yours?)` returns the part's props, including `children` and `ref`, merged with yours by the rules above. Pass
  your props to it rather than spreading them separately, so handlers and refs chain instead of overwriting.
- `state` is an accessor for the part's model: the `segment`, `day`, `column`, …
- The function may return any JSX, including text.

A part reads `render` once, when it is created. Switching a live part between `render` and no `render` does not
re-render it.
