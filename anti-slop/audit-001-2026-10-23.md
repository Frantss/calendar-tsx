# antislop audit 001: docs site prose

- **Date:** 2026-10-23
- **Mode:** After (audit only; nothing is changed until findings are approved by number)
- **Scope:** every MDX file in `apps/docs/content` (`docs/` and `shared/`, 95 files), the comments in `apps/docs/examples`,
  and the comments in `apps/docs/src` and `apps/docs/vite.config.ts`
- **Skills applied:** `antislop` (core), `antislop-copywriting`, `antislop-code`. UI, layout and contrast rules are out
  of scope: the site uses Fumadocs' default design, and the request covered the docs' text.

**Priority.** The core maps priority to the cited rule's tier. R-02 bans the em dash outright, so findings 1 to 3 are
HIGH. The copywriting skill files its style tells (findings 4 to 6) under R-02 and R-36, which are also Hard Gate rules,
but none of these is an em dash or a fabricated claim, so grading them HIGH would overstate them. They are graded LOW.

## Findings

### 1. HIGH (R-02): em dashes as connectors in the docs introduction

`apps/docs/content/docs/index.mdx:11-12`: "The core computes a render-ready view model — month grids with spanning bars,
time grids with overlap lanes and resource columns, lists — on TanStack Store and Temporal." Two em dashes set off an
aside; R-02 forbids them in text.

### 2. HIGH (R-02): em dash in the Themes page description, in all three roots

`apps/docs/content/docs/{react,solid,core}/styling/themes.mdx:3`: "Plain CSS for the parts — a positioning base,
built-in themes and a density." The description also shows as the page subtitle and in search results.

### 3. HIGH (R-02): em dash as the empty value in table cells

An em dash marks "no default" or "no model prop" in 21 table cells:

- `apps/docs/content/shared/reference/options.mdx:14-20, 26-28` (Default column, 10 cells)
- `apps/docs/content/shared/views/time-grid.mdx:17, 20, 21, 71, 74, 77`
- `apps/docs/content/shared/features/events.mdx:10` (`allDay` for timed events)
- `apps/docs/content/shared/views/month.mdx:58`, `apps/docs/content/shared/views/list.mdx:39` (Model prop column)
- `apps/docs/content/docs/react/reference/hooks.mdx:37`, `apps/docs/content/docs/solid/reference/primitives.mdx:40`
  (Default column)

These are placeholders, not prose connectors, but R-02 bans the character in any text. The dash is also ambiguous: in
the options table it means "required", and elsewhere it means "none".

### 4. LOW (copywriting: inline-header lists): bold lead-ins that repeat the item

List items start with a bold label that the sentence after it restates:

- `apps/docs/content/shared/features/events.mdx:16-20` ("**Midnight ends.** A timed event ending exactly at midnight
  ends on the previous day…")
- `apps/docs/content/docs/core/adapters/writing-an-adapter.mdx:22-24` ("**Create once.** Creating a calendar per render…")
- `apps/docs/content/docs/{react,solid,core}/getting-started/quick-start.mdx` "What it does" lists (4 bold lead-ins each)
- `apps/docs/content/docs/{react,solid}/getting-started/installation.mdx:10-13` (bold package names)

Together they repeat across the getting-started pages. Bold that defines a term is not included: `period` and
`range` in navigation, **Tracked** and **Read once** in options, **Unlayered CSS** and **Layered CSS** in customizing.

### 5. LOW (copywriting: excessive quotation marks): "now" and "today" in scare quotes

The concept of the current time is put in quotes instead of named:

- `apps/docs/content/shared/features/now.mdx:3, 14, 21`
- `apps/docs/content/shared/features/server-rendering.mdx:5`
- `apps/docs/content/shared/reference/options.mdx:42` ("today")

These shared files reach every root, so each occurrence shows on up to three pages. Where the text means the
`state.now` field, code formatting carries it; elsewhere, "the current time" says it without quotes.

### 6. LOW (copywriting: inanimate subject, human verb): abstractions that decide or assume

- `apps/docs/content/shared/features/now.mdx:3`: '"Now" decides which day is today and where the now indicator sits.'
- `apps/docs/content/shared/reference/options.mdx:41-42`: the time zone "also decides which day is 'today'".
- `apps/docs/content/shared/styling/themes.mdx:50`: "The layout assumes the parts are nested as…"

Each gives a mind verb to something that only sets a value, where "sets" or a named actor (`base.css` expects) is
plainer.

## Checked, not flagged

- **Zero hits:** R-16 buzzwords and the skill's empty vocabulary, minimizers (simply, just, easily), filler phrases,
  signposting, negative parallelism, authority tropes, stacked hedges, all-caps emphasis, emoji, exclamation marks,
  generic CTAs (R-15), statistics or claims without a source (R-17, R-36).
- **En dashes in ranges** (`22:00–00:00`, `1–7`, `Monday–Sunday`): R-02 bans the em dash only, and these mark ranges.
- **Passive voice** where the object is the topic ("`initialNow` is read once", "the instance is created on the first
  render"): the skill's not-a-ban case, and not repeated by default across pages.
- **Quoted UI strings** ("Go to", "More"): quotes that carry meaning, as the skill allows.
- **The contrast figures** in the high-contrast and RevenueCat sections: computed from the CSS, so they are sourced.
- **Code comments** (53 in `apps/docs/examples`, 3 in `apps/docs/src` and `vite.config.ts`): each explains a reason,
  a constraint or a result the reader of an example needs. None is decorative, obvious, step narration, a vague TODO or
  an end marker, and none runs past two lines.
